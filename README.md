# 🎲 가챠 확률 검증 — 게임 QA 포트폴리오

확률형 아이템이 **공시 확률대로 동작하는지** 기획서 기반으로 TC를 설계하고,
의도적으로 버그를 주입한 빌드에서 이를 검출 → 리포트 → 재검증까지 진행한 프로젝트입니다.

**결과 요약**
- 버그 빌드: TC-1(확률표 합계), TC-2(등급별 확률) Fail → 1등·4등 설정값 오류 2건 발견 (Critical)
- 수정 빌드 재검증: TC-1~10 전체 Pass → 두 티켓 Closed
- 판정 기준: 전체 유의수준 1%, 4개 등급 동시 검사이므로 등급별 0.25% (다중검정 보정)

---

게임사가 공시한 가챠 확률과 실제 뽑기 결과가 통계적으로 맞는지 검증합니다.
가상의 뽑기 상자를 수천 번 열어 보는 시뮬레이션으로, 설정한 확률대로 아이템이 나오는지 확인할 수도 있습니다.

## 로또 상자 시뮬레이션

`Lotto Test` 상자를 설정한 횟수(`OPENS`)만큼 열어, 등급별로 설정 확률대로 나오는지 검증합니다.
매 개봉은 **독립시행**입니다. 이전 결과에 따라 확률이 바뀌지 않고, 천장이나 보정도 없습니다.

| 등급 | 확률 |
|---|---|
| 1등 | 1% |
| 2등 | 10% |
| 3등 | 88.9% |
| 4등 | 0.1% |

### 실행

```bash
pytest tests/test_lotto.py
```

VSCode에서는 `tests/test_lotto.py`를 열고 오른쪽 위 ▷ 버튼을 누르거나, 왼쪽 🧪 테스트 탐색기에서 실행합니다.

### 출력 예

pytest 기본 출력 대신, 비전공자도 읽을 수 있는 보고서로 출력합니다.

```
========================================================================
  가챠 확률 검증 테스트 보고서
========================================================================
  테스트 목적  뽑기 상자가 설정(공시)한 확률대로 아이템을 내주는지 통계로 검증합니다.
  실행 모드    버그 (bug): 버그를 넣은 상자 (lotto_buggy.py)
  개봉 횟수    100,000회
  ...

[TC-2] 등급별 확률 검증  (상자 검증)
  확인 내용: Lotto Test [버그 버전] 상자를 100,000번 열어 등급별로 설정 확률대로 나오는지 비교
  결과:      ❌ 실패
             등급   설정 확률   기대 횟수   실제 횟수   실제 확률      차이       p-value   판정
             1등        1.00%     1,000.0           0       0.00%   -1.00%p   0.0001 미만   ❌
             ...
  해석:      3개 등급이 설정 확률과 다르게 나왔습니다.
             - 1등: 1.00%로 설정했는데 실제로는 0.00% (기대 1,000번 → 실제 0번, 1,000번 덜 나옴, 한 번도 안 나옴)
               우연히 이 정도 차이가 날 확률은 100만 번에 1번도 안 될 만큼 드문 일입니다.
...
  전체 결과 요약 (TC별 ✅/❌ 표) → 최종 판정 → 용어 설명
```

- **상자 검증** TC는 선택한 모드(정상/버그)의 상자를 검사하고, **도구 점검** TC는 검증 도구 자체가 제대로 동작하는지 확인합니다(모드와 무관).
- `-v`(`--verbose`)를 붙이면 개별 개봉 결과와 누적 집계도 보여 줍니다.
- `--raw`를 붙이면 보고서 대신 pytest 기본 출력(트레이스백 포함)이 나옵니다. 오류 위치를 찾을 때 쓰세요.

### 확률·횟수·모드 바꾸기

`tests/test_lotto.py` 위쪽 값을 고치면 됩니다.

```python
MODE = "normal"  # "normal": 정상 상자 / "bug": 버그 버전 상자
OPENS = 1_000    # 1_000(천) / 10_000(만) / 100_000(십만) 등
```

파일을 고치지 않고 명령줄에서 바꿀 수도 있습니다.

```bash
pytest tests/test_lotto.py --mode bug --opens 100000
pytest tests/test_lotto.py -v                          # 개별 개봉·누적 집계까지 보기
python tests/test_lotto.py --mode bug --opens 10000   # 파일 직접 실행도 같은 옵션 사용
```

확률은 `LOTTO_TEST`에서 바꿉니다. 확률 합이 100%가 아니면 오류로 알려 줍니다.

### 버그 버전 상자 (`lotto_buggy.py`)

검증 도구가 실제로 버그를 잡아내는지 확인하는 용도입니다. 정상 상자 코드(`lotto.py`)는 그대로 두고,
공시 확률표는 똑같이 보여 주되 실제 뽑기에만 버그를 넣었습니다.

| 버그 | 내용 | 잡아내는 곳 |
|---|---|---|
| ① | 1등 1% → 0.0000001% | 결과 요약에서 1등 불일치 (1,000회부터 잡힘) |
| ② | 4등이 절대 안 나옴 | 결과 요약에서 4등 불일치 (1,000회로는 못 잡고, 10,000회부터 잡힘) |
| ③ | 확률표 합계가 100%가 아님 (98.9000001%) | `test_rate_table_sums_to_100` 실패. 모자란 1.1%가 2·3등으로 몰려 3등이 약 89.89%로 나오며, 10,000회 이상에서 3등 불일치로도 보임 |

### 결과를 읽을 때 알아둘 점

- **실행할 때마다 결과가 달라집니다.** 보고서의 `seed` 값을 `simulate(..., seed=값)`에 넣으면 같은 결과를 그대로 재현할 수 있습니다.
- **정상 상자도 드물게 "불일치"가 나옵니다.** 우연히 크게 치우치는 경우로, 전체 유의수준을 1%로 잡아 약 200번에 1번 이하 수준입니다.
- **1,000회로는 희귀 등급 검증이 어렵습니다.** 4등(0.1%)은 1,000번에 평균 1번 나오므로 0번이어도 정상으로 판정됩니다. 정밀하게 보려면 `OPENS`를 늘리세요.

## 공시 확률 검정 (직접 사용)

실제 뽑기 기록이 있다면 숫자만 넣어 바로 검정할 수 있습니다.

```python
from gacha_validator import test_rate

r = test_rate(pulls=10_000, hits=72, advertised_rate=0.01)
print(r.observed_rate, r.p_value, (r.ci_low, r.ci_high))
print("공시 확률과 일치" if r.is_consistent() else "공시 확률과 불일치 (α=0.05)")
```
